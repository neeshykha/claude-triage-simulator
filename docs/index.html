How it was measured

Tickets
60 synthetic tickets written to mirror multifamily smart-home support (smart locks, thermostats, leak sensors, access panels, the resident app). Each has an author role (resident, property manager, or maintenance), the ticket text, and a labeled severity and routing team. No real customer or company data.
Classifier
triage.py calls the Claude Code CLI once per ticket (claude -p … --model sonnet --output-format json) from the repo folder, so CLAUDE.md is loaded as the instructions: the P1–P4 taxonomy, seven routing teams, an escalation override for safety-related devices left broken for more than 24 hours, and the confusable patterns. The prompt contains only the ticket text and author role, not the labels.
Scoring
eval.py compares each prediction to its label by exact match, separately for severity and routing. A severity miss counts as under-triage if the prediction is less urgent than the label and over-triage if more. The audit groups are fixed ticket IDs listed in eval.py.
Limits
One run. The per-ticket predictions file is generated locally and not committed; the scorecard lists every miss, so every ticket not listed above matched its label. --model sonnet is an alias, and the scorecard doesn’t record which model version or date the run used.

Every number on this page is copied from results/scorecard.md as committed; the evaluation was not re-run for this page. Ticket text is from data/tickets.jsonl.
